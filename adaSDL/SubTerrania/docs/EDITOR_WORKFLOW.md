# SubTerrania Editor Workflow

The editor is now treated as the primary application. The SDL game runtime should eventually read the data produced by the editor.

## Tool model

Only one editing tool should be active at a time:

- Select: select tiles or entities.
- Brush: place the selected tile or entity from the palette.
- Erase: remove an entity or clear a terrain tile.
- Pan: reserved for viewport movement.
- Path: add motion nodes to the currently selected entity.

Grid is not a tool. Grid is a view overlay.

## Basic object workflow

1. Choose an entity from the left palette, such as Platform, Enemy, Miner, Gate, or Fuel.
2. Click the map to place it.
3. Switch to Select.
4. Click the entity.
5. Use the right inspector to review its generated name, type, components, transform, and motion path data.

Object names are generated by kind, such as `Platform_01`, `Enemy_01`, and `Miner_01`.

## Motion path workflow

1. Select an entity.
2. Click `Edit Path / Add Nodes` in the right inspector.
3. Click map locations to add path nodes to that entity.
4. Use `Apply Path Fields` if you want to manually edit the first two nodes.
5. Use `Clear Path` to remove that entity's current path.

Path nodes belong to the selected object. They are not global map points.

## Motion path meaning

A node is a point in the world:

```text
Node 1: X, Y, Time
Node 2: X, Y, Time
```

A segment is the movement between two nodes. Timing belongs to the segment implied by the node times. Later phases should expose segment-level fields such as duration, easing, wait time, loop, ping-pong, snap, linear, smooth, and arc.

## Mission objectives

Sub-Terrania objectives should be rules, not just green blocks on the map. For example:

```text
Objective: Rescue Miners
Required: 1
Then: Return To Base
```

Miners are placed as entities. The objective panel should later define the win rules.

## Entity behavior categories

Future entity templates should support:

- Enemies with animations, movement paths, firing arcs, and weapons.
- Bosses with phases, animations, attack timing, and multi-part behavior.
- Destructible objects with pixel-mask destruction.
- Items with glowing animation and used state.
- Laser redirectors, pendulums, mirrors, and repeaters.
- Miners with patrol areas and rescue behavior.
- Platforms with landable/crushing behavior and predefined movement paths.
- Water zones that change gravity.
